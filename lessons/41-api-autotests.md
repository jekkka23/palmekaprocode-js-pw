# 41. Автотест учебного REST API

[Открыть урок на сайте](https://palmekaprocode.ru/courses/qa-auto-javascript/lessons/api-autotests)

## Зачем это нужно в автотесте

UI-тест проверяет то, что видно в браузере. API-тест обращается к тому же учебному продукту напрямую и быстро замечает неверный статус или форму данных. Здесь прочитаем активных клиентов без изменения их записей.

## Что уже надо знать и подготовить

Проверьте эти условия до запуска примера.

- Завершите урок независимых тестов: Playwright, request, expect и сохраненная сессия уже знакомы.
- Откройте https://palmekaprocode.ru/practice/book-api под учебным аккаунтом, найдите свой Bearer-токен и скопируйте его. Токен может быть перевыпущен, поэтому старое значение перестанет работать.
- В терминале из корня palmekaprocode-js-pw выполните read -rs TRAINING_API_TOKEN && export TRAINING_API_TOKEN, вставьте токен из своего тренажера и нажмите Enter. Ввод не отобразится. Не сохраняйте токен в .js, коммитах и скриншотах.
- Продолжайте с playwright.config.js из урока сохраненного входа. Он задает baseURL и запускает setup перед спеками.

## Сначала разберем слова

Учебный REST API полигона содержит клиентов и заказы. На странице "Учебный REST API" ученик получает личный токен. Playwright fixture request отправляет реквесты прямо к этому API и позволяет проверять статус и тело ответа.

- **API-реквест**: обращается к серверу напрямую, без клика по странице.
- **Bearer-токен**: передается в заголовке Authorization и определяет ученика для API-песочницы.
- **Статус 200**: означает успешное чтение; тело JSON содержит items и pagination.
- **Контракт**: согласованная форма входа и ответа: метод, путь, статус и поля.

## Как это работает

Начнем с чтения активных клиентов: GET не изменяет данные, поэтому тест можно безопасно повторять. Затем отдельным тестом проверьте 400 для неверного page. Токен храните вне репозитория.

- Взять личный токен на странице тренажера
- Передать Authorization: Bearer
- Отправить GET /api/training/customers?active=true
- Проверить 200, массив items и активность каждой записи

## Файл tests/api/customers.spec.js

Создайте папку tests/api и сохраните в ней файл customers.spec.js. BASE_URL уже задан в конфиге, а TRAINING_API_TOKEN берется из терминала. Скопируйте весь пример с комментариями.

[Открыть готовый файл](../tests/api/customers.spec.js)

**Обратите внимание.** Cookie от входа на сайт и Bearer-токен учебного API - разные способы авторизации. Для /api/training нужен именно Bearer. Если данные аккаунта ранее менялись, число клиентов может отличаться; проверяем правило, а не точное количество.

## Как запустить

Выполняйте шаги по порядку.

- Сохраните файл tests/api/customers.spec.js и проверьте, что TRAINING_API_TOKEN задан в текущем терминале.
- Из корня palmekaprocode-js-pw выполните npx playwright test tests/api/customers.spec.js --project=chromium --reporter=list. Зависимость setup сначала сохранит вход, затем запустит эту спеку.

## Какой результат ожидать

При действующем токене будет 2 passed: один setup и один API-тест. GET вернет 200, а все элементы items будут с active: true. Если токен не задан, тест остановится на проверке переменной; если устарел, проверка статуса покажет 401.

```text
2 passed
```

## Команды для копирования

Выполняйте команды из корня palmekaprocode-js-pw. Копируйте строку целиком, без текста пояснения.

**Обратите внимание.** Токен берите в /practice/book-api под тем же аккаунтом. Команда ввода не показывает его в терминале. После нее вставьте токен и нажмите Enter.

**Вставьте свой API-токен после запуска этой команды и нажмите Enter**

```bash
read -rs TRAINING_API_TOKEN && export TRAINING_API_TOKEN
```

**Запустить API-тест**

```bash
npx playwright test tests/api/customers.spec.js --project=chromium --reporter=list
```

## Что поменять для проверки понимания

Меняйте по одному пункту, сначала предскажите итог, потом запустите пример и верните исходную строку.

- Замените active=true в адресе на active=false, а ожидаемое значение в every на false. Итог снова 2 passed: теперь проверяются неактивные клиенты.
- Верните исходный запрос и временно ожидайте статус 201 вместо 200. Итог будет 1 passed и 1 failed: сервер по-прежнему отвечает 200.
- Верните статус 200 и удалите TRAINING_API_TOKEN только из текущего терминала командой unset TRAINING_API_TOKEN. Setup пройдет, API-тест упадет с сообщением о переменной. Затем задайте токен заново.
