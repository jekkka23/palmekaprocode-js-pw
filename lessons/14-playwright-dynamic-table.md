# 14. Элементы: веб-таблица

[Открыть урок на сайте](https://palmekaprocode.ru/courses/qa-auto-javascript/lessons/playwright-dynamic-table)

## Зачем создавать запись внутри теста

В веб-таблице строка, добавленная вручную, не обязана существовать при следующем запуске теста. Поэтому автотест сам создает нужную запись и сразу проверяет ее. Тогда результат не зависит от того, что осталось после других проверок.

На тренажере "Веб-таблица" добавим сотрудника с известной почтой, затем найдем именно эту строку и сравним имя и почту. В следующем уроке запустим несколько таких проверок независимо.

- Открыть пустую форму записи
- Заполнить обязательные поля и сохранить
- Найти новую строку по почте и проверить данные

## Что подготовить

Продолжайте в qa-playwright с рабочим setup. Откройте https://palmekaprocode.ru/practice/web-tables под учебным аккаунтом. Кнопка "Добавить запись" открывает форму, а после сохранения строка появляется в таблице.

Создайте tests/web-tables/pages и tests/web-tables/helpers. Данные предыдущих тренажеров этому тесту не нужны.

- Проверьте, что radio-button.spec.js отдельно дает 2 passed.
- Нажмите "Добавить запись" вручную и посмотрите обязательные поля.
- Создайте три файла .js по путям ниже.

## Сначала разберем слова

Спека задает сотрудника как объект data. Страница открывает форму и заполняет поля. Хелпер после сохранения ищет строку по data.email, поэтому не перепутает ее с исходными строками таблицы.

- **Тестовая запись**: данные, которые тест создает для своей проверки. Здесь это одна строка сотрудника.
- **Предусловие**: данные, нужные до проверки результата. Новую строку тест создает сам.
- **Предикат XPath**: условие в квадратных скобках. Здесь tr[td[...]] выбирает строку с нужной почтой в ячейке.
- **toContainText**: ассерт, который ждет часть текста внутри найденной строки.

## Как это работает

У страницы после каждого нового открытия свой набор строк. Проверка не рассчитывает на чужой результат: она готовит запись, затем сверяет имя и почту в той же вкладке. Сохраненная сессия нужна только для доступа к тренажеру.

- Открыть /practice/web-tables
- Нажать "Добавить запись"
- Заполнить имя, фамилию, почту, возраст, зарплату и отдел
- Сохранить и проверить найденную по почте строку

## Первый файл: tests/web-tables/pages/web_tables_page.js

Страница хранит поля формы и метод поиска строки. Обратите внимание на обязательные возраст и зарплату: значения для них передаются строками в fill().

[Открыть готовый файл](../tests/web-tables/pages/web_tables_page.js)

**Обратите внимание.** Метод rowWithEmail возвращает локатор строки, а не ее текст. Хелпер сможет проверить несколько значений в одной найденной строке.

Хелпер создает запись в той же вкладке, где затем проверяет результат. Функцию runRecordCase можно будет повторно вызвать с другими данными в следующем уроке.

[Открыть готовый файл](../tests/web-tables/helpers/functions_web_tables.js)

## Третий файл: tests/web-tables/web-tables.spec.js

Спека задает одну новую запись. Хелпер создаст ее перед проверкой, поэтому предварительно добавлять строку руками не надо.

[Открыть готовый файл](../tests/web-tables/web-tables.spec.js)

## Как запустить и что увидеть

Сохраните три файла. В корне qa-playwright выполните npx playwright test tests/web-tables/web-tables.spec.js --project=chromium --reporter=list.

Setup подготовит сессию, затем основной тест создаст строку. Успешный запуск заканчивается 2 passed. Новая строка содержит "Мария" и "maria.table@example.ru".

```text
2 passed
```

**Обратите внимание.** Если строка не появилась, проверьте обязательные поля формы. Тест ищет только строку с почтой из data и не зависит от исходных сотрудников таблицы.

## Что поменять для проверки понимания

Меняйте одну строку и перед запуском предсказывайте результат.

- В web-tables.spec.js замените firstName на "Анна". Хелпер введет и проверит новое имя, поэтому итог снова 2 passed.
- Верните имя. В хелпере замените data.firstName только в ассерте на "Другое имя". Строка сохранится, но основной тест упадет на шаге 3; итог 1 passed и 1 failed.
- Верните data.firstName. Повторный запуск должен дать 2 passed.
