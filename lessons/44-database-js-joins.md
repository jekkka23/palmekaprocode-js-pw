# 44. Автопроверка связей через JOIN

[Открыть урок на сайте](https://palmekaprocode.ru/courses/qa-auto-javascript/lessons/database-js-joins)

## Зачем это нужно в автотесте

Заказ хранит customer_id, а имя покупателя лежит в другой таблице. JOIN дает возможность проверить связь целиком и поймать ситуацию, когда заказ указывает не на того покупателя.

## Что уже надо знать и подготовить

Проверьте эти условия до запуска примера.

- Пройдите SELECT через JavaScript: здесь остается тот же request, cookie и POST к SQL-песочнице.
- В SQL-песочнице посмотрите столбцы orders.customer_id и customers.id. Сначала вручную выполните JOIN из примера.
- Используйте сохраненный вход из tests/auth.setup.js и проект chromium. Данные аккаунта не меняем.

## Сначала разберем слова

Один заказ связан с покупателем через customer_id. В UI можно увидеть номер заказа, но проверка связи требует посмотреть обе таблицы. JOIN возвращает заказ и имя соответствующего покупателя одной строкой.

- **JOIN**: соединяет строки двух таблиц по совпадающим ключам.
- **INNER**: JOIN оставляет только найденные пары; LEFT JOIN сохраняет и строки без пары справа.
- **Инвариант**: правило, которое должно оставаться верным после действия, например имя покупателя соответствует заказу.
- **Повторная проверка**: читает БД после изменения и доказывает, что новое состояние сохранилось.

## Как это работает

Для изменений сначала проверяйте чтение. Позже можно создать запись через API и выполнить SELECT для ее id. Если тест меняет личную SQL-базу через INSERT или UPDATE, используйте отдельный аккаунт и очищайте только свои данные. Сброс всей базы не подходит для общего аккаунта.

- Написать JOIN для orders и customers
- Отправить action: execute для задачи joins-order-customer
- Проверить columns и rows
- Проверить evaluation.passed
- Не менять данные общего аккаунта

## Как читать SQL в этом тесте

Редактор SQL-песочницы не разрешает комментарии внутри запроса. Разберем строку sql здесь, прежде чем запускать файл.

- SELECT orders.id, customers.name берет номер заказа и имя покупателя из разных таблиц.
- FROM orders задает левую таблицу: по одной исходной строке на заказ.
- JOIN customers ON customers.id = orders.customer_id ищет покупателя, чей id совпадает с ключом заказа.
- ORDER BY orders.id фиксирует порядок строк, чтобы проверка полного результата была повторяемой.
