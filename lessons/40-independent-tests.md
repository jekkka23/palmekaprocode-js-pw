# 40. Данные и независимые проверки

[Открыть урок на сайте](https://palmekaprocode.ru/courses/qa-auto-javascript/lessons/independent-tests)

## Зачем тесту независимость

Если второй тест читает строку, которую создал первый, он проходит только при одном порядке запуска. Запуск по одному или параллельно обнаружит такую зависимость. В хорошей спеке каждый test готовит свои данные сам.

Вернемся к веб-таблице из блока "Элементы". Напишем два теста с разными сотрудниками. Каждый вызовет уже готовый runRecordCase: откроет свою страницу, создаст строку и проверит результат. Потом запустим только второй тест.

- Создать две независимые проверки
- Запустить обе вместе
- Запустить вторую отдельно и сравнить вывод

## Что подготовить

Нужен тот же palmekaprocode-js-pw. Из урока веб-таблицы должны существовать tests/web-tables/pages/web_tables_page.js и tests/web-tables/helpers/functions_web_tables.js с экспортом runRecordCase. Оставьте их без изменений.

Создайте рядом файл tests/web-tables/independent.spec.js. Setup авторизации и проект chromium уже настроены. Каждому test Playwright выдаст свою вкладку page; веб-таблица внутри нее начнется с исходного состояния.

- Сначала убедитесь, что web-tables.spec.js отдельно дает 1 passed.
- Проверьте путь импорта ./helpers/functions_web_tables.js в новом файле.
- Создайте independent.spec.js в той же папке web-tables.

## Сначала разберем слова

В первом test будут данные Марии, во втором - Бориса. Оба вызывают тот же runRecordCase(page, data). Внутри хелпера запись создается до проверки, поэтому второй test ничего не берет из первого.

- **Независимый тест**: проверка, которая создает все свои условия и проходит отдельно от соседних test.
- **page**: отдельная вкладка, которую Playwright дает каждому test. Состояние веб-таблицы в новом page начинается заново.
- **--grep**: параметр запуска Playwright, который оставляет тесты с подходящим названием.
- **Тестовые данные**: значения, которые конкретный test передает хелперу для создания и проверки строки.

## Как это работает

Совместный запуск выполнит два теста, итог 1 passed. Запуск с --grep по названию второго теста выполнит только его, итог 1 passed. Разница в количестве тестов покажет, что второй работает сам.

- Каждый test получает свой page
- Каждый вызывает runRecordCase со своими данными
- Хелпер создает и проверяет строку внутри того же test
- Отдельно запускаем вторую проверку через --grep

## Как запустить оба теста

В корне palmekaprocode-js-pw выполните npx playwright test tests/web-tables/independent.spec.js --project=chromium --reporter=list. Каждый тест сам вызывает login, затем создает свою запись.

Последняя строка успешного запуска - 2 passed: два самостоятельных теста. Каждый сам вызывает login. Порядок этих двух тестов не влияет на их результат.

```text
2 passed
```

## Как запустить только второй тест

Выполните npx playwright test tests/web-tables/independent.spec.js --project=chromium --grep "вторая запись Бориса" --reporter=list. Фильтр по названию оставит только второй test. Он сам вызовет login.

Ожидаемый итог - 1 passed: тест Бориса. Он сам вызывает login. Мария в этом запуске не создается, и проверка Бориса все равно проходит.

```text
1 passed
```

**Обратите внимание.** Этот пример относится к веб-таблице, которая хранит строки в состоянии открытой страницы. Данные учебного API и БД сохраняются отдельно: там понадобятся уникальные значения и очистка своих записей.

## Команды для копирования

Выполняйте команды из корня palmekaprocode-js-pw. Копируйте строку целиком, без текста пояснения.

**Запустить оба независимых теста**

```bash
npx playwright test tests/web-tables/independent.spec.js --project=chromium --reporter=list
```

**Запустить только второй тест**

```bash
npx playwright test tests/web-tables/independent.spec.js --project=chromium --grep "вторая запись Бориса" --reporter=list
```

## Что поменять для проверки понимания

Перед каждым запуском предскажите количество прошедших тестов.

- Во втором test замените только firstName на "Анна". Запустите оба теста: итог 2 passed, потому что хелпер введет и проверит новое имя второй записи.
- Верните имя. Поставьте во втором test ту же почту, что у Марии: "maria.independent@example.ru". Запустите оба теста: итог 2 passed, потому что у каждого своя веб-таблица в отдельной вкладке.
- Верните почту и запустите только второй test с --grep. Итог снова 1 passed.
