# 6. Команды Playwright для автотестов

[Открыть урок на сайте](https://palmekaprocode.ru/courses/qa-auto-javascript/lessons/playwright-commands)

## Зачем изучать команды Playwright

Первый тест уже открыл браузер и дошел до тренажера. Теперь разберем, какие команды внутри теста управляют страницей и как проверить результат каждого действия. В конце вы самостоятельно заполните форму, выберете чекбокс и значение списка.

Это учебная лаборатория команд в одном файле. Позже разнесем действия по странице, хелперу и спеке, а отдельный блок XPath покажет, как находить локаторы по реальному HTML.

- Открыть страницу и найти нужный элемент
- Ввести текст, нажать кнопку, выбрать чекбокс и пункт списка
- Проверить адрес, значение поля и результат на экране

## Что умеет Playwright

Playwright управляет браузером программно: открывает страницы, нажимает кнопки, вводит текст, работает с вкладками, файлами и уведомлениями. Playwright Test добавляет запуск спек, ожидания, проверки и отчет о результате. В этом проекте уже настроен Chromium; при отдельной установке Playwright может работать также с Firefox и WebKit.

В дальнейших уроках используем эти возможности для UI, API и диагностики падений. Сейчас возьмем только базовые действия с элементами, чтобы за каждой командой был виден конкретный результат на тренировочном поле.

- Страница: page.goto открывает адрес из baseURL.
- Локатор: page.locator находит элемент; XPath внутри готовых строк подробно разберем позже.
- Действие: fill, click, check и selectOption меняют состояние страницы.
- Проверка: expect сравнивает фактическое состояние с ожидаемым и ждет его появления.
- Другие возможности: hover, press, работа с новыми вкладками, загрузка файлов, скриншоты и API будут в следующих разделах.

## Новые слова без путаницы

Команда действия отвечает на вопрос "что сделал пользователь". Ассерт отвечает на вопрос "что после этого получилось". Одного клика без проверки для автотеста недостаточно.

- **page**: вкладка браузера, которую Playwright передает тесту; у нее есть адрес и содержимое.
- **locator**: объект для поиска конкретного элемента; строку xpath=... пока берем готовой, составлять ее научимся позже.
- **fill**: заменяет содержимое текстового поля заданной строкой.
- **click**: нажимает кнопку или ссылку после ожидания ее доступности.
- **check**: переводит чекбокс в выбранное состояние; повторный вызов не снимет галочку.
- **selectOption**: выбирает option внутри HTML-списка select по ее value.
- **expect**: начинает проверку; toHaveValue, toHaveText и toBeChecked ждут нужного состояния.

## Как читать цепочку команд

В выражении page.locator("xpath=//input[@id='full-name']").fill("Анна Тестовая") первая часть находит поле, а fill записывает в него текст. await дожидается завершения действия. Затем expect(...).toHaveValue(...) проверяет, что браузер действительно хранит нужную строку.

Клик по "Отправить" только запускает действие. Итог проверяем отдельно в блоке результата. check выбирает родительский пункт "Рабочий стол", после чего проверяем дочерние "Заметки" и "Команды". selectOption получает значение option "mentor", а не видимую подпись "Наставник".

- page.goto("/practice/text-box") - открыть тренажер с учетом baseURL.
- locator.fill("...") и expect(locator).toHaveValue("...") - действие и проверка поля.
- locator.click() и expect(result).toContainText("...") - действие и проверка ответа.
- locator.check() и expect(locator).toBeChecked() - выбрать и проверить галочку.
- locator.selectOption("mentor") и expect(locator).toHaveValue("mentor") - выбрать и проверить HTML-список.

**Обратите внимание.** Playwright обычно сам ждет, пока элемент станет пригодным для действия, а проверки expect повторяются до ожидаемого состояния или таймаута. Не добавляйте паузу в миллисекундах после каждого клика.

## Команды в терминале

Команды внутри спеки управляют браузером, а команда npx playwright test запускает сами спеки из терминала. Эти варианты используют уже установленный пакет проекта.

- npx playwright test tests/playwright-commands.spec.js --reporter=list - выполнить только новый файл и увидеть построчный отчет.
- npx playwright test tests/playwright-commands.spec.js --headed --reporter=list - выполнить тот же тест с видимым окном браузера.
- npx playwright test --list - показать найденные тесты без запуска браузера.
- npx playwright test --help - посмотреть доступные параметры команды.

## Как запустить и какой вывод ожидать

В корне qa-playwright сохраните файл tests/playwright-commands.spec.js. Запустите только его командой npx playwright test tests/playwright-commands.spec.js --reporter=list. Старые спеки команда не запускает.

Ожидаемый итог - 1 passed. Это один test, даже если внутри него три перехода: отдельными тестами они пока не объявлены. После заполнения текстовой формы появится почта anna@example.ru; чекбокс покажет "Рабочий стол, Заметки, Команды"; селект сохранит роль mentor. Playwright покажет название теста и время, которое зависит от сети и компьютера.

```text
1 passed
```

**Обратите внимание.** Если тест не прошел, найдите первую неудачную строку. Ошибка на /login относится ко входу; ошибка на /practice/text-box - к форме; на /practice/check-box - к галочкам; на /practice/select-menu - к выбору роли. Не исправляйте все сразу.

## Что поменять для проверки понимания

Меняйте одну строку, сначала предскажите исход, запустите ту же команду и верните строку обратно перед следующим опытом.

- В проверке имени замените ожидаемое "Анна Тестовая" на "Мария Тестовая", не меняя fill. Проверка toHaveValue упадет: итог 1 failed.
- Верните имя. Уберите строку check() у Рабочего стола, не меняя проверки дочерних пунктов. toBeChecked для Заметок упадет: итог 1 failed.
- Верните check(). Замените selectOption("mentor") на selectOption("admin" и оставьте проверки mentor. Проверка роли упадет: итог 1 failed. Верните mentor, чтобы получить 1 passed.
