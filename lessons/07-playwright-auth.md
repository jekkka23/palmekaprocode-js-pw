# 7. Вход в закрытый полигон

[Открыть урок на сайте](https://palmekaprocode.ru/courses/qa-auto-javascript/lessons/playwright-auth)

## Зачем это нужно в автотесте

В прошлом уроке каждый тест сам открывал /login и вводил почту с паролем. Когда тестов станет много, повторный вход будет занимать время и заслонять проверку самого тренажера.

Здесь мы один раз войдем под учебным аккаунтом в подготовительном тесте, сохраним сессию и передадим ее другому тесту. В конце второй тест откроет "Текстовые поля" сразу, без заполнения формы входа.

- Подготовительный тест создает файл с состоянием браузера
- Playwright открывает новый тест с этим состоянием
- Проверка тренажера начинается сразу с нужной страницы

## Что подготовить

Продолжайте в корне palmekaprocode-js-pw. Там уже есть корневой package.json и установленный @playwright/test; первые спеки и их конфиг остаются в intro/qa-playwright. Теперь создайте корневые tests/auth.setup.js и playwright.config.js для всех следующих уроков. Вводные файлы не переносите.

Учебный аккаунт test-auto@palmekaprocode.ru с паролем test-auto имеет доступ только к тренировочному полю. Он нужен для примера ниже. Вход в вашем обычном Chrome не переносится в браузер Playwright.

- Откройте https://palmekaprocode.ru/login под учебным аккаунтом и убедитесь, что в верхнем меню есть "Тренировочное поле".
- В корне palmekaprocode-js-pw создайте файл .gitignore или откройте существующий. Добавьте отдельной строкой playwright/.auth/ - туда попадет файл с действующей сессией.
- Убедитесь, что в терминале открыта папка palmekaprocode-js-pw. Команда npx playwright --version должна показать номер версии.

**Обратите внимание.** Папку playwright/.auth/ добавьте в .gitignore до первого запуска. Ее содержимое позволяет войти без пароля, поэтому в репозиторий его не отправляют.

## Сначала разберем слова

После входа сайт выдает браузеру cookie сессии. Playwright сохранит ее в локальном файле. Когда откроется тест тренажера, Playwright создаст для него новый контекст и загрузит туда сохраненные данные.

- **Сессия**: вход, который сайт запоминает после правильной почты и пароля. Благодаря ей следующие страницы узнают ученика.
- **Cookie**: небольшие данные браузера, по которым сайт находит сессию. Здесь в cookie находится идентификатор входа, а не пароль.
- **Контекст браузера**: изолированное окружение теста со своими cookies. Новый тест обычно получает новый контекст и не наследует вход предыдущего сам по себе.
- **storageState**: сохраненные cookies и другие данные контекста. Playwright запишет их в student.json, а затем загрузит для нового теста.
- **Подготовительный проект**: группа тестов setup, которая выполняет вход раньше основных проверок.
- **Зависимость проекта**: правило dependencies: тесты проекта chromium запускаются после успешного setup.
- **Секрет**: настоящий пароль, токен или файл с действующей сессией. Такие данные не печатают в логах и не добавляют в репозиторий.

## Как это работает

Сам факт существования student.json не означает, что вход будет вечным: сессия может истечь. В нашей настройке setup запускается перед основным тестом и создает свежий файл. Учебные почта и пароль открыто указаны в примере по договоренности; для личных и рабочих аккаунтов так делать нельзя.

- Открыть /login в setup и ввести учебные данные
- Дождаться кабинета и ссылки на тренировочное поле
- Записать cookies в playwright/.auth/student.json
- Запустить новый тест с этим файлом и открыть /practice/text-box

## Как запустить

Сохраните все три файла в palmekaprocode-js-pw. Убедитесь, что папка playwright/.auth/ уже записана в .gitignore. В терминале из корня проекта выполните команду ниже.

- Сначала Playwright найдет tests/auth.setup.js в проекте setup, войдет под учебным аккаунтом и создаст playwright/.auth/student.json.
- Потом Playwright загрузит student.json для tests/saved-session.spec.js и откроет /practice/text-box без повторного ввода пароля.
- Если нужно отдельно обновить файл сессии, выполните npx playwright test tests/auth.setup.js --project=setup --reporter=list. Основной запуск выше и так обновляет его автоматически.

```bash
npx playwright test tests/saved-session.spec.js --project=chromium --reporter=list
# Запускаем только новую спеку; ее зависимость setup Playwright выполнит сам.
```

## Какой результат ожидать

В выводе появятся две строки с успешными тестами: сначала [setup] для входа, затем [chromium] для тренажера. Последняя строка содержит 2 passed. Время в скобках у всех будет разным, поэтому сравнивайте именно число прошедших тестов.

После запуска появится файл playwright/.auth/student.json. В нем есть данные сессии, а не учебный пароль. В tests/saved-session.spec.js нет ни перехода на /login, ни fill с почтой и паролем: это и есть результат повторного использования входа.

```text
2 passed
```

**Обратите внимание.** Старые спеки из прошлого урока пока по-прежнему вводят логин сами, потому что эти действия остались в их коде. Новый тест показывает, как писать следующие спеки без повторного входа.

## Команды для копирования

Выполняйте команды из корня palmekaprocode-js-pw. Копируйте строку целиком, без текста пояснения.

**Запустить тест с автоматическим setup**

```bash
npx playwright test tests/saved-session.spec.js --project=chromium --reporter=list
```

**Отдельно обновить файл сессии при необходимости**

```bash
npx playwright test tests/auth.setup.js --project=setup --reporter=list
```

## Что поменять для проверки понимания

Меняйте одну строку за раз. Перед запуском предскажите результат, затем выполните ту же команду и сравните вывод.

- В tests/saved-session.spec.js замените только путь /practice/text-box на /practice/check-box. Setup пройдет, а основной тест упадет: вместо заголовка "Текстовые поля" на странице будет "Чекбоксы". В итоге увидите 1 passed и 1 failed.
- Не меняя путь, замените только ожидаемый заголовок на "Чекбоксы". Теперь оба теста пройдут, в конце будет 2 passed. Так видно, что сессия подходит для разных закрытых тренажеров.
- Верните обе строки к исходному варианту перед домашним заданием.

## Если запуск не прошел

Разделите ошибку по этапам: setup отвечает за вход и файл сессии, обычная спека - за открытие нужной страницы и проверку заголовка.

- Если setup не дошел до /account, проверьте, что скопированы учебные почта и пароль и что сайт открывается вручную.
- Если не найден student.json, проверьте строку dependencies: ["setup"] и запускайте тест с --project=chromium из папки palmekaprocode-js-pw. Не используйте --no-deps для первого запуска.
- Если вместо тренажера открывается /account, проверьте доступ учебного аккаунта к полю и запустите setup заново. Если открылся /login, сохраненная сессия не подошла - обновите ее тем же запуском.

## Что делать с настоящими секретами

Этот логин и пароль специально выделены для учебного кода. В рабочем проекте нельзя вписывать личный пароль в спеку: его передают через переменные окружения, а файл с действующей сессией исключают из Git.

Файл student.json позволяет действовать от имени учебного аккаунта, пока сессия жива. Поэтому .gitignore нужен даже тогда, когда в самом JSON не написан пароль. Для API-тренажера позже понадобится отдельный Bearer-токен; cookie браузерного входа его не заменяет.

**Обратите внимание.** Сохранение сессии ускоряет UI-тесты. Оно не делает тесты зависимыми друг от друга: каждому тесту Playwright создает отдельный контекст с копией сохраненного состояния.
