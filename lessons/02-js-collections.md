## Сначала разберем слова

Один объект описывает одного сотрудника: фигурные скобки { } окружают его свойства name и department. Массив rows собирает такие объекты вместе: квадратные скобки [ ] окружают весь список, а запятые разделяют соседние записи. Так можно обработать весь список, даже если в нем станет больше сотрудников.

- **Объект**: объединяет свойства одной записи. Например, { name: "Ирина", department: "QA" } описывает одну строку таблицы.
- **Массив**: хранит несколько значений по порядку внутри квадратных скобок. В rows каждое значение будет объектом сотрудника.
- **Элемент массива**: одно значение внутри массива. В нашем примере один элемент rows - это одна строка таблицы.
- **filter**: создает новый массив только из элементов, для которых условие вернуло true. Исходный массив не меняется.
- **map**: создает новый массив из результатов преобразования каждого элемента. Мы превратим строки сотрудников в их имена.
- **row**: временное имя для текущего элемента массива. При переборе rows под этим именем по очереди окажутся объекты Ирины, Максима и Олега.
- **=>**: запись короткой функции. Слева стоит текущий объект row, справа - действие или проверка, результат которой получает filter либо map. Подробнее функции разберем в следующем уроке.
- **length**: показывает количество элементов массива. У rows.length будет 3, у qaRows.length - 2. В первом уроке это же свойство считало символы в строке student.name.
- **join**: соединяет элементы массива в одну строку. Разделитель ", " можно заменить на "; " или другой текст.

## Как это работает

Выражение (row) => row.department === "QA" можно читать так: "возьми очередную строку и проверь ее отдел". JavaScript повторит эту проверку для всех объектов. Затем map пройдет только по оставшимся строкам и возьмет у каждой name. Так получатся два новых массива: объекты сотрудников QA и отдельно их имена.

- rows содержит три объекта в том же порядке, что и строки таблицы
- filter подставляет каждый объект в row, проверяет отдел и сохраняет совпадения в qaRows
- map проходит по qaRows и сохраняет значения name в qaNames
- length считает элементы каждого массива, а join превращает массив имен в текст для вывода

## Проследите, как filter проверяет строки

Внутри filter имя row не означает конкретного сотрудника. Метод три раза подставит в него очередной объект из rows. Выражение справа от => каждый раз даст true или false. В новый массив попадут только строки с true.

## Что получилось после каждого шага

Обратите внимание на тип элементов. В rows и qaRows лежат целые объекты с name и department. Метод map берет из каждого объекта qaRows только name, поэтому элементы qaNames - уже строки, а не объекты. Запись (row) => row.name означает: "для текущего объекта верни его имя".

**Обратите внимание.** Распространенная путаница: map вызывается у qaRows, поэтому Максим уже не участвует в сборе имен. join нужен только для красивого вывода: он превращает массив имен в строку "Ирина, Олег".

**Обратите внимание.** Если команда node не найдена, проверьте установку Node.js через node --version. Если не найден lesson-2.js, проверьте расположение javascript/lesson-2.js и откройте терминал в корне проекта.

## Какой вывод ожидать

С исходными данными терминал напечатает ровно три строки. Первая показывает 3 объекта в rows. Вторая показывает 2 объекта после filter. Третья показывает имена после map и join, в том же порядке, что и в исходном массиве.

```text
Всего строк: 3
Строк QA: 2
Имена QA: Ирина, Олег
```

**Обратите внимание.** Если вместо 2 получилось 0, проверьте регистр букв в названии отдела. Сравнение === считает "qa" и "QA" разными строками.
