## Зачем это нужно в автотесте

API может вернуть правильный статус, хотя связанные данные в базе уже неверны. Сначала научимся читать учебную таблицу вручную: так дальше будет понятно, что именно проверяет автотест БД.

## Что уже надо знать и подготовить

Проверьте эти условия до запуска примера.

- Достаточно знать объект и массив из первых уроков и отличать API-респонс от данных, которые хранит сервер.
- Войдите под учебным аккаунтом и откройте https://palmekaprocode.ru/practice/sql-lab. Здесь нужен доступ к тренировочному полю; Node.js пока не запускаем.
- Откройте тему "WHERE и условия", выберите задачу "Активные покупатели" и найдите редактор SQL. В нем выполняется один запрос без SQL-комментариев, поэтому пояснения ниже кода не копируйте в редактор.

## Сначала разберем слова

После API переходим к данным за ответом сервера. В SQL-песочнице шесть связанных таблиц. Каждому ученику выдается собственный набор, поэтому можно исследовать строки без доступа к данным других учеников.

- **База данных**: хранит связанные наборы записей. В SQL-песочнице это учебный магазин.
- **Таблица**: набор строк одного типа: customers хранит покупателей, orders хранит заказы.
- **Столбец**: описывает свойство строки, например name или status; id отличает одну строку от другой.
- **Внешний ключ**: orders.customer_id указывает на customers.id и связывает заказ с покупателем.

## Как это работает

Проверка БД начинается с вопроса: что должно храниться после действия? Сначала учимся читать данные через SELECT. FROM выбирает таблицу, WHERE ограничивает строки, ORDER BY делает порядок результата предсказуемым.

- Открыть карту таблиц SQL-песочницы
- Выбрать задачу "Активные покупатели"
- Прочитать несколько строк SELECT
- Оставить активные записи через WHERE
- Упорядочить результат через ORDER BY

## Первый запрос к учебной базе

Скопируйте в редактор только четыре строки SQL. Пояснения размещены сразу под запросом, потому что редактор не принимает SQL-комментарии. Запрос ничего не меняет.

```sql
SELECT id, name
FROM customers
WHERE active = 1
ORDER BY id;
```

**Обратите внимание.** В SQL-песочнице используется SQLite. SELECT не меняет строки. Кнопка также сверяет результат с задачей "Активные покупатели". После изменений для проверки понимания таблица покажет новые строки, а задача может получить отметку "Неверно". Верните исходный запрос, чтобы снова получить зачет.

## Разбираем пример по строкам

Прочитайте каждую строку в том же порядке, что и в примере.

- Строка 1 - SELECT выбирает только id и name. Остальные столбцы покупателя не попадут в результат.
- Строка 2 - FROM customers указывает таблицу, из которой читаем записи.
- Строка 3 - WHERE active = 1 оставляет только покупателей с признаком активности 1.
- Строка 4 - ORDER BY id сортирует их по id. Точка с запятой завершает единственный запрос.

## Как запустить

Выполняйте шаги по порядку.

- Откройте https://palmekaprocode.ru/practice/sql-lab под аккаунтом с доступом к полю. В теме "WHERE и условия" выберите задачу "Активные покупатели" и вставьте четыре строки в редактор.
- Нажмите "Выполнить и проверить SQL". Смотрите таблицу результата под редактором; команда node или npx для этого урока не нужна.

## Какой результат ожидать

В исходном наборе шесть активных покупателей: id 101, 102, 104, 105, 106 и 107. Вы увидите два столбца id и name именно в таком порядке и сообщение "Правильно! SQL выполнен, задача зачтена.". Если личный набор уже меняли, строки могут отличаться; WHERE все равно исключит active = 0, а ORDER BY сохранит порядок по id.

```sql
101 | Анна Смирнова
102 | Максим Орлов
104 | Илья Петров
105 | Мария Волкова
106 | Денис Ким
107 | Елена Соколова
```

## Что поменять для проверки понимания

Меняйте по одному пункту, сначала предскажите итог, потом запустите пример и верните исходную строку.

- Замените active = 1 на active = 0. В исходном наборе останутся два покупателя: 103 Ольга Белова и 108 Павел Романов. Задача про активных покупателей покажет "Неверно".
- Верните active = 1 и замените ORDER BY id на ORDER BY id DESC. Те же шесть строк пойдут от 107 к 101, но задача ожидает порядок по возрастанию.
- Верните сортировку и добавьте в SELECT столбец active. В результате появится третий столбец, во всех оставшихся строках он будет равен 1. Задача ожидает только id и name.
