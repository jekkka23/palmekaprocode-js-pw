# 9. XPath: ищем поля и кнопку

[Открыть урок на сайте](https://palmekaprocode.ru/courses/qa-auto-javascript/lessons/xpath-basics)

## Зачем автотесту XPath

Автотесту нужен точный способ найти поле, кнопку и результат в дереве страницы. XPath описывает путь к элементу через его тег, атрибуты и связи с соседними элементами. В следующих UI-уроках курса будем записывать локаторы только через XPath.

Здесь вы найдете элементы формы "Текстовые поля" в Chrome DevTools, проверите, что каждый путь дает один результат, а затем запустите первый Playwright-тест с xpath=.

- Найти нужный элемент в DOM
- Составить короткий XPath с устойчивым атрибутом
- Проверить XPath в DevTools и Playwright

## Сначала разберем слова

Сначала читаем HTML, а потом составляем путь. У формы есть id text-box-form, у поля имени id full-name. Выражение //form[@id='text-box-form']//input[@id='full-name'] связывает их: среди потомков конкретной формы нужен input с нужным id.

- **DOM**: дерево HTML-элементов текущей страницы, которое видно в панели Elements DevTools.
- **XPath**: выражение для поиска элемента в DOM. Например, //input[@id='full-name'] находит input с указанным id.
- **//**: поиск подходящего элемента среди потомков, а не только на следующем уровне дерева.
- **@**: обращение к атрибуту элемента: @id, @type и другим.
- **Предикат**: условие в квадратных скобках: [@id='full-name'] отбирает нужный input.
- **xpath=**: явное указание Playwright, что строка в page.locator написана на XPath.
- **Уникальность**: один XPath должен находить ровно один элемент для конкретного действия.

## Как это работает

В панели Elements нажмите Command+F на macOS или Ctrl+F на Windows и вставьте XPath. DevTools покажет количество совпадений. Ищите 1 из 1; при 0 проверьте текущую страницу и написание атрибутов, при нескольких совпадениях уточните форму или поле. В Playwright ту же строку передаем в page.locator с префиксом xpath=.

- Осмотреть HTML нужного элемента
- Взять стабильный id или атрибут внутри понятной области
- Проверить выражение в поиске Elements
- Добавить xpath= и toHaveCount(1) в тесте

## Ищем поле имени в DevTools

На странице нажмите правой кнопкой на поле "Имя и фамилия" и выберите "Просмотреть код". В дереве найдите <form id="text-box-form">, а внутри него <input id="full-name">. Не копируйте длинный путь от html и body: он зависит от лишних контейнеров.

Составьте //form[@id='text-box-form']//input[@id='full-name']. Здесь //form выбирает форму, [@id='text-box-form'] уточняет ее, а //input[@id='full-name'] находит поле внутри. Вставьте выражение в поиск панели Elements. Должно быть одно совпадение.

- Если написали только //input, увидите несколько полей и не поймете, какое заполнится.
- Если написали @id без квадратных скобок, XPath не отберет конкретный input.
- Если поле не нашлось, проверьте, что открыта именно /practice/text-box, а не список тренажеров.

## Ищем почту, кнопку и результат

В той же форме поле почты имеет type="email", а кнопка отправки type="submit". Проверьте в DevTools выражения //form[@id='text-box-form']//input[@type='email'] и //form[@id='text-box-form']//button[@type='submit']. Каждое должно найти один элемент.

Блок результата появляется только после отправки. После ручного заполнения и отправки найдите <div id="text-box-output"> через //div[@id='text-box-output']. До отправки поиск вернет 0, после - 1: XPath всегда проверяется на текущем состоянии DOM.

**Обратите внимание.** Для следующих UI-тестов используем короткие XPath по атрибутам и смысловым областям. Полный абсолютный путь вроде /html/body/div[2]/main/div[3] ломается при перестановке контейнеров. Синтаксис Playwright: https://playwright.dev/docs/other-locators
