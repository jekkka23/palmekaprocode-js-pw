# 11. Элементы: текстовые поля

[Открыть урок на сайте](https://palmekaprocode.ru/courses/qa-auto-javascript/lessons/test-layers-example)

## Зачем это нужно в автотесте

В архитектурном уроке мы открывали тренажер и проверяли его заголовок. Теперь начнем проверять поведение первого раздела поля - "Элементы". На экране "Текстовые поля" тест введет известные имя и почту, отправит форму и сравнит результат с введенными данными.

Оставим структуру из трех файлов: страница выполняет действия, хелпер описывает шаги и ожидания, спека передает конкретные данные. XPath из предыдущего блока хранится в файле страницы: если id поля изменится, правка останется в одном месте.

- Ввести данные в форму через подписи полей
- Отправить форму
- Проверить, что результат содержит те же значения

## Что подготовить

Продолжайте в palmekaprocode-js-pw. Вход делает tests/helpers/login.js. Спека вызывает await login(page) и не содержит почту с паролем.

Откройте https://palmekaprocode.ru/practice/text-box вручную. На странице есть поля "Имя и фамилия" и "Электронная почта", кнопка "Отправить" и блок "Результат", который появляется после отправки.

- Создайте папки tests/text-box/pages и tests/text-box/helpers в проекте palmekaprocode-js-pw.
- Убедитесь, что команда из архитектурного урока для training-field.spec.js дала 1 passed.
- Оставьте playwright.config.js и tests/helpers/login.js без изменений. Все новые файлы ниже имеют расширение .js.

## Сначала разберем слова

У теста есть исходные данные: имя "Иван Петров" и почта "ivan@example.ru". Спека передаст их хелперу. Страница заполнит форму этими значениями, а хелпер после отправки сравнит блок результата с тем же объектом data.

- **XPath**: путь к элементу в DOM. Здесь он находит поля внутри формы по id и type.
- **page.locator**: метод Playwright, который создает локатор из строки xpath=... .
- **fill**: действие, которое заменяет содержимое поля заданным текстом.
- **toContainText**: ассерт, который ждет нужный текст внутри элемента. Если значение не появится, тест упадет.
- **data**: объект со входными значениями теста. Хелпер получает его из спеки и использует при вводе и сравнении.

## Как это работает

Проверка только кнопки ничего не говорит о результате. Поэтому последний шаг проверяет оба значения в #text-box-output. Этот блок появляется после отправки формы; ожидание Playwright дождется его без фиксированной паузы.

- Спека передает data в runTextBoxCase(page, data)
- Страница открывает тренажер и заполняет поля
- Хелпер проверяет имя и почту в результате
- Setup готовит вход, а основной тест не повторяет авторизацию

## Как запустить и что увидеть

Сохраните три файла по указанным путям. В корне palmekaprocode-js-pw выполните npx playwright test tests/text-box/text-box.spec.js --project=chromium --reporter=list.

В начале спека вызывает login из файла tests/helpers/login.js. Последняя строка успешного запуска содержит 1 passed. В блоке "Результат" тест найдет "Иван Петров" и "ivan@example.ru". Эти значения совпадают с объектом, переданным из спеки.

```text
1 passed
```

**Обратите внимание.** Если тест падает после входа, ищите причину в трех шагах хелпера формы. Проверяйте локатор поля, отправку и текст результата.

## Что поменять для проверки понимания

Перед каждым изменением предскажите результат. Меняйте только одну строку, запустите ту же команду и сравните вывод.

- В text-box.spec.js замените только имя на "Мария Соколова". Ожидайте 1 passed: хелпер введет новое имя и будет проверять именно его через data.name.
- В хелпере временно замените data.email в последнем ассерте на "wrong@example.ru". Setup пройдет, основной тест упадет на шаге 3. В итоге будет 1 passed и 1 failed.
- Верните data.email. Повторный запуск должен снова закончиться 1 passed.

## Что дальше в разделе Элементы

Раздел "Элементы" содержит несколько разных действий. Этот пример дает основу: действие страницы, ожидаемый результат и отдельный тест. Следующие проверки будем добавлять по одной, сохраняя ту же структуру.

- Чекбоксы и радиокнопки: выбор состояния и проверка выбранных значений.
- Веб-таблица и динамические свойства: создание своих строк и ожидание изменения состояния.
- Кнопки, ссылки и файлы: разные типы кликов, переходы, загрузка и скачивание.

**Обратите внимание.** Не создавайте один длинный test на все тренажеры сразу. Каждый самостоятельный флоу должен запускаться отдельно с собственным page и вызовом login.
